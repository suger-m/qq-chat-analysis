# 按成员总结单群或所有群消息

用户要求总结某个人的群发言、按人回顾一段时间或跨群归纳时，使用 `person` 获取原料。
该命令执行成员筛选和上下文提取；由 Agent 阅读原料后完成内容总结。

## 调用

以下示例中的 `$qq` 是本次加载技能的 `scripts/qq.ps1`。Bash 或 uv 入口使用相同参数。

```powershell
# 某人在一个群最近 7 天的发言，保存为 UTF-8 原料
& $qq person '<成员ID>' --group '目标群名' --days 7 -o person-context.txt

# 某人在当前账号所有本地群中指定日期范围的发言
& $qq person '<成员ID>' --all-groups --from '2026-10-01' --to '2026-10-21' -o person-context.txt

# 最近 300 条目标发言（全群汇总后的总上限），前后各保留 5 条相邻消息
& $qq person '<成员ID>' --all-groups --limit 300 --context-before 5 --context-after 5

# 只读取指定日的已有快照，输出结构化原料
& $qq person '<成员ID>' --group '目标群名' --date '2026-10-21' --no-fresh --json -o person-context.json
```

`--no-fresh` 仅用于用户接受旧快照的情况。默认沿用普通查询的源库新鲜度检查。

## 身份与范围

- 优先指定 QQ 号或 NT UID。完整昵称/群名片也能查询，命令只接受唯一匹配；重名要求
  改用 ID。跨群使用统一账号身份匹配，群名片按每个群单独显示。
- `--group` 与 `--all-groups` 必选其一。群名匹配不唯一时要求明确群号或唯一群名。
- “所有群”是当前所选 QQ 账号的本地快照中可读的群聊记录。私聊和其他登录账号不在范围内。
  `--account` 可沿用通用选项指定账号。
- `--date` 指定单日，`--days` 指定滚动最近 N 天；二者互斥，也不与 `--from/--to` 混用。
- `--from/--to` 支持日期和 ISO 日期时间。日期型 `--to` 包含整天；日期时间型 `--to`
  是不包含的上界。未带时区的时间按运行机器的本地时区解释。
- 有时间范围时默认输出范围内全部目标发言；没有时间范围时默认最近 300 条。
  `--limit N` 在成员筛选后、所有群合并排序后限制目标发言总量，`--limit 0` 为不限。
  目标统计排除系统事件；相邻上下文另计。

## 保留必要上下文

每条选中的目标发言默认保留同群前后各 3 条相邻消息，同时限制在前后 15 分钟内。
`--context-before`、`--context-after` 调整条数（各 0–100），`--context-minutes` 调整分钟数。
条数为 0 时关闭对应方向的相邻消息。

目标发言自带的引用保留原发送者和引用内容；能依据原序号、发送者和时间定位的引用
原消息也会补入。相邻消息和补入的引用原消息都遵守指定时间范围。已包含在目标消息中的
旧引用摘要保留为引用，不能把它当成时间范围内新增的一次发言。

上下文按同群消息去重并保留关联目标。输出中的 `role=target` 表示目标发言，
`role=context` 表示辅助上下文；后者可能包含他人或该成员未列入目标配额的相邻发言。
原消息、嵌入引用和系统提示分别保留署名，旁人的话不能归到目标成员名下。

JSON 按群分组，每条消息保留群 ID、发送者、时间、字符串消息 ID、媒体及上下文关联。
文本按群和日期编排；重名发言者使用区分后的名称，成员表与 `validate --context` 兼容。

## 阅读、总结与报告

1. 完整阅读 `person` 原料，先查看目标、群范围、时间上下界和覆盖情况。
2. 围绕目标成员归纳主要讨论主题、观点、回答、决策及明确待办。旁人上下文仅用来解释
   发言的起因、回复对象或后续结果。跨群结果写明相关群名与时间，不能拼成虚构对话。
3. 消息量、每小时分布和观点归属均以目标发言为准。`hourly` 只计目标消息；旁人上下文、
   重复补入的引用和系统事件不重复计数。
4. 用户要求 HTML 时，阅读分析指南，按现有报告结构编写 analysis.json，再使用
   `validate ... --context person-context.txt` 与 `html` 渲染。`person --json` 输出的是原料，
   需要先由 Agent 编写分析 JSON。单群报告可填写实际 `gid`；跨群报告省略 `gid`，
   `group` 使用“某成员 · 跨群发言总结”等标题，在议题或时间线中注明来源群。

```powershell
& $qq validate analysis.json --context person-context.txt --fix -o analysis.validated.json
& $qq html analysis.validated.json --theme light -o person-report.html
```

## 覆盖与输出保护

查看 JSON 的 `stats` 或文本头部的覆盖说明。命中总数、输出目标数、辅助上下文数和
因 `--limit` 未输出的数量分开列出。坏页、群发现失败、身份无法解析和缺失正文都会记录；
发生这些情况时，只能总结实际读到的内容，并说明范围限制。

扫描先按群的消息序号/分片复合游标读取元信息，再筛选成员。正文只为最终目标和必要上下文
解码；无“先取全群最近 N 条再找成员”的隐藏窗口。读取失败的群会记录并继续处理其他群。

文本默认 `--max-chars 200000`。超限时命令报错并保留完整消息边界；按日期或群分批提取、
显式限制目标数量，或用 `--max-chars 0` 输出全部。JSON 不受此字符保护限制。
命令退出成功不代表覆盖完整，仍需看 `stats.complete` 和明细。

原料包含必要的本地身份映射，`-o` 必须写到技能包外。原料、分析 JSON 与私密数据保持本地，
分享 HTML 前按技能说明检查自由文本、昵称和图片。
